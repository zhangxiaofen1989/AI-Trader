1) 项目说明与适用人群

本页面面向中文用户，目标是帮助你在 Windows / macOS / Linux 上完成 OpenClaw 部署。无论你是第一次接触，还是要在生产环境重装，都可以按照本文逐步执行。

提示：不同版本 OpenClaw 的依赖可能不完全一致，建议先在官方仓库确认版本说明，再执行下方命令。

2) 安装前准备（系统与依赖）

  • 操作系统：Ubuntu 22.04+ / macOS 13+ / Windows 11（建议 WSL2）。
  • Git：用于拉取源码。
  • Docker & Docker Compose：用于容器化安装。
  • Python 3.10+：用于源码安装。
  • Node.js 18+（如 OpenClaw 版本包含前端控制台）。

执行以下命令检查环境：

git --version
python3 --version
docker --version
docker compose version
node --version

3) 方式 A：Docker 快速安装（推荐）

适合希望快速可用、依赖隔离、便于迁移的用户。

步骤 1：拉取项目

git clone <OPENCLAW_OFFICIAL_REPO_URL> openclaw
cd openclaw

步骤 2：复制配置文件

cp .env.example .env

步骤 3：修改关键配置

# 常见配置示例
APP_ENV=production
APP_PORT=3000
DATABASE_URL=postgres://openclaw:password@db:5432/openclaw
REDIS_URL=redis://redis:6379
OPENAI_API_KEY=your_key_here

步骤 4：启动服务

docker compose pull
docker compose up -d

步骤 5：查看日志确认启动

docker compose ps
docker compose logs -f --tail=200

4) 方式 B：源码安装（开发者常用）

步骤 1：创建 Python 虚拟环境

python3 -m venv .venv
source .venv/bin/activate
pip install -U pip setuptools wheel

步骤 2：安装后端依赖

pip install -r requirements.txt

步骤 3：安装前端依赖（若有 web 目录）

cd web
npm install
npm run build
cd ..

步骤 4：初始化数据库

# 以下命令根据项目文档调整
python manage.py migrate
python manage.py init_admin

步骤 5：启动服务

python manage.py runserver 0.0.0.0:3000

5) 配置详解（.env 与常见参数）

变量含义建议值
APP_ENV运行环境dev / staging / production
APP_PORT服务端口3000（避免与其它服务冲突）
DATABASE_URL数据库连接建议使用 PostgreSQL
REDIS_URL缓存/队列redis://redis:6379
API_KEY模型或服务密钥通过环境变量注入，不写入代码
安全建议：生产环境请配合 Nginx + HTTPS，且将密钥放入 CI/CD Secret 或服务器环境变量中。

6) 启动与验证

  1. 浏览器访问：http://localhost:3000
  2. 健康检查接口：curl http://localhost:3000/health
  3. 查看实时日志：docker compose logs -f 或源码模式下查看控制台输出。

7) 故障排查清单

  • 端口占用：lsof -i :3000，改用其它端口后重启。
  • 镜像拉取慢：配置镜像加速，或先 docker pull 分步执行。
  • 数据库连不上：确认用户名、密码、主机和防火墙策略。
  • 依赖报错：删除缓存后重新安装：pip cache purge / npm cache clean --force。
  • 权限问题：Linux 下检查目录属主：sudo chown -R $USER:$USER .

8) 升级与回滚策略

升级建议

git fetch --all
git checkout <target_version_tag>
docker compose pull
docker compose up -d --remove-orphans

回滚建议

  • 升级前备份数据库与 .env。
  • 保留上一个稳定版本 tag。
  • 如果异常，立即切回旧 tag 并恢复数据库快照。
